# 014 - Responsive shell, native Settings, on-screen keyboard (brief)

Status: decisions approved 2026-10-10. Study and evidence: `reports/022-responsive-shell-study.md` (read it before any phase; it holds the code inventory, the framework design, the render harness design, the phase table and effort). Builds on 012 (F1 keyboard, F2 multi-board) and 013 (Pi 3A+ bring-up, T1-T4 done, phase 0 keyboards done).

## Decisions (user)
- **Option B:** one code base, a layout layer places and sizes elements for the logical screen (480x320 up to 1280x720 and square 720x720). Landscape logical canvases only; **portrait not supported (D12)**, the display backend rotates portrait-native panels.
- **D1 Settings look:** keep today's centre-highlight roller look; on wide screens a **narrow centred roller** (width capped near today's), with margins. Settings leaves the 320x170 compat window and fills the screen (touch-native + keyboard).
- **D2:** the deck kept compat Settings during P2-P3 behind a runtime switch (`APPLAUNCH_SETTINGS_UI=native|compat`, since removed), then one deliberate change to native at P3e (done: native whenever the dpi-scaled backend exists, no switch, no compat path; see "P3e as implemented: the flip" at the end). **D9:** delete the legacy roller renderer and the ~7,440 lines of dead LVGL examples at the end.
- **D3:** an unmigrated page may open from the native Settings in dev builds only; a release goes native on a board only when every page visible on that board is migrated.
- **D4:** `APPLAUNCH_PANEL_MM=WxH` in `board.conf` (install.sh writes it for known panels), then fbdev mm, then 11.3 px/mm. **D5:** rows 7 mm, buttons and toolbar 9 mm, floors 40 px / 48 px.
- **D6:** the fallback on-screen keyboard is built on the responsive shell (P2b), not on the old compat window. Rules in 012 F1 still hold (Auto/Off setting, only when no physical keyboard, asleep BT keyboard counts as present for N minutes, no hide key, on-screen Esc always sends its release).
- **D7:** migrate the SSH form with the Apps/sudo phase.
- **D8:** stock-app toolbar stays a **bottom bar** on every screen class (scaled window above it).
- **D10:** export size/tokens internally now; publish the app contract (`cp0_ui_metrics.h`, VFB2, `.desktop` keys, docs) in P5 after Settings proves it. **D11:** the shared status bar may scale above 100 % on Large; update the apps' copies in the same change.
- **Out of scope for now:** the M5Stack Store, stock CardputerZero apps and the other native apps (Snake, Tank, IP Panel, CLI, Python): they keep running as a scaled fixed canvas window. User's published apps become responsive later (P5 contract).
- Transitional rule (report 022 section 6): anything not migrated goes through the unchanged compat path.

## Home grid design rule (user feedback 2026-10-10, from the HackBerry 720x720 run)
Tiles must stay close to SQUARE (aspect about 1:1 to 1.2:1) on every screen; the grid dimensions (columns x rows) follow from the available area, they are not fixed at 3x2. Today's 640x480 grid stretched onto 720x720 gives tall 216x305 tiles with dead space: wrong. Rule for P1c (Controller design, to be confirmed on harness mockups):
- target tile = about 17-24 mm per side (deck today about 17 mm, Pi 3A+ today about 24 mm), minimum 9 mm touch target is already met; columns = round(available width / (target tile + gap)), rows = floor(available height / tile), the leftover is spread as even gaps/margins; the icon scales to about 50 % of the tile, the label sits under it; more apps than cells scroll vertically as today.
- the deck 640x480 (3x2, 192x188) and the Pi 3A+ 480x320 (3x2, 146x125) stay PINNED as they are.
- indicative results (available area under the status bar): 800x480 -> 4x2 (about 185x190), 720x720 -> 3x3 (about 218x200), 1280x720 -> 6x3 (about 195x195) or 5x3.

### Final rule as implemented (P1c, `shell_computed_grid` in cp0_ui_metrics.c; computed sizes only)
- bar = class header token; pad = clamp(2 mm in px, 10, 24); avail = (w - 2 pad) x (h - bar); target tile = 20 mm (at least 120 px).
- cols = clamp(round((avail_w + pad) / (target + pad)), 2, 8); tile_w = (avail_w - (cols-1) pad) / cols.
- rows = max(2, floor((avail_h - pad) / (0.92 tile_w + pad))); tile_h = (avail_h - (rows+1) pad) / rows. If tile_h/tile_w is outside [0.85, 1.2], rows +-1 is taken when it gets closer to 0.95 (one row is allowed, for short wide canvases where two rows are too flat).
- The rule's cols (cols0) and cols0 +- 1 (2..8) are all evaluated this way: a result inside [0.85, 1.2] beats one outside; among those inside the tile width closest to the 20 mm target wins (a tie keeps cols0), among those outside the aspect closest to 0.95. A tile still above 1.2 tile_w is capped there and the grid is centred vertically (`top_extra`).
- icon = half the short side, multiple of 8, at least 32 (lv_image stretch, no new assets); label font = min(class body text, tile_w/7), snapped, at least 14; radius = RADIUS_L token; borders, status strip, title and toolbar stay the base preset's (deck from 400 px of height, compact below); a canvas whose tiles would be under 40 px keeps the base grid.
- Results (harness `home_grid` scene and unit tests): 800x480 @9.2 px/mm 4x2 177x185; 720x720 @10 3x3 213x192; 1280x720 @11.6 6x3 186x188; 1024x600 @6.6 7x4 131x119; short canvases (one row scrolls vertically): 800x320 3x1 236x234, 1024x400 3x1 310x298 (@6.6: 7x2 131x152), 1280x400 4x1 291x298. Arrow navigation and scrolling use the new cols as before.

## Toolbar rule (user feedback 2026-10-10, HackBerry 720x720: the toolbar took 370 of 720 px)
The bottom toolbar has a FIXED physical height from the tokens, never "the rest of the screen": buttons 9 mm (about 90-100 px on the boards seen), plus margins, so about 100-110 px on every screen class (deck 140 and Pi 3A+ 100 stay PINNED). The stock-app window (integer scale of 320x170) is centred in the space above the toolbar, black margins around it; on a square or large screen the leftover room stays black (decision D8: always a bottom bar) until a later design uses it. A native, responsive page (Settings after P2) does not use this toolbar at all: it fills the screen and takes touch directly.

## Native Settings host (P2a, as implemented)
Switch (P2a to P3d; removed in P3e): `APPLAUNCH_SETTINGS_UI=native|compat`, default compat. Since P3e native runs whenever the dpi-scaled display exists (`native_ui::enabled()`), otherwise the legacy roller pages in the compat window run (stock CardputerZero, SDL simulator, emulator). The launcher asks the page at launch time (`UISettingTreePage::native_display_now()`, `launch.h` `page_native_choice`): native = `begin_page(true)`, full screen on the native display, plain pointer touch, no toolbar.

Look and behaviour (approved design): single column, drill-in, one level at a time (sections; a section's entries with the current value right-aligned in green, toggles, the Brightness slider; a value list with a blue check mark, Enter / tap applies and goes back). Roller (revised after the Controller review of 2026-10-11): black ground, centre row on a #2b2b2b bar, its text 0.43 x the row height in Montserrat Bold, values 0.9 x that (sizes snapped to the even font set, odd -> next larger); other rows 8 % smaller per step (at least 70 %) and 20 % fainter (at least 35 %) so two or three rows each side stay readable down to the screen edge; orange #ff6a3d chevrons (two strokes, 0.55 x the row height wide) centred in the roller while rows exist that way; width capped 560 px (640 Large) and centred, full height, rows = ROW token; slider and switch sized from the centre text. Per size (row / centre text / neighbours d1..d4 / value): 480x320 44 / 20 / 18 18 16 14 / 18; 640x480 79 / 34 / 32 30 26 24 / 32; 800x480 64 / 28 / 26 24 22 20 / 26; 720x720 70 / 30 / 28 26 24 22 / 28; 1280x720 81 / 36 / 34 30 28 26 / 32. Header = the home grid's status bar (56 / 40 / 56 / 64 / 64 px): the home title at its exact place and size (`native_ui::add_title`: "Settings", "Settings > Screen" when it fits up to the Esc button, else the shorter path, else dots), an on-screen `Esc` button (TARGET wide, TARGET high but not above the bar minus 2 x status_top, i.e. 40 / 30 / 40 / 40 / 40 px, centred on the clock pill's line, SPACE_M left of the strip's Bluetooth icon measured with the strip renderer by `native_ui::status_strip_left()`, the toolbar Esc key's look) that calls the page's back action directly, and the shared status strip (`native_ui::add_status_icons`, added when the screen is loaded so it reads the state at once). A one-line status line (the value pages' messages, gate refusals; the latest message wins, a page clears only its own) lies over the top left of the body. Touch: drag scrolls and snaps to a row, a tap moves the highlight, a tap on the highlighted row opens / applies / toggles. Keys: Up / Down (lists wrap, value lists stop), Enter, Esc (back; home from level 1); Left / Right change a slider, elsewhere Right opens and Left goes back as in today's Settings.

Widgets (`ext_components/cp0_lvgl`, no geometry in pages): `cp0_ui_roller.h/.c` (pure C: roller page layout from the tokens, centre row, snap, row under a point, step, text falloff, fade, width cap; `tests/test_ui_roller.c`), `cp0_ui_widgets.hpp` with `cp0::ui::Page` (scaffold: header, title, status line, Esc) and `cp0::ui::Roller` (rows: Nav with value, Choice with check, Toggle, Slider), `src/cp0_ui_page.cpp`, `src/cp0_ui_roller_widget.cpp`.

Host (`projects/APPLaunch/main/ui/settings`): `settings_native_host.*` walks the existing tree; `settings_node_kind()` (settings_page.cpp, next to the tree) classifies each node from its own page factory and API: Section (roller_page_factory, bluetooth_roller_page_factory; refreshed first by `settings_prepare_section()`, shared with the legacy factories), Choice (the value pages: Brightness incl. gpio On / Off, DarkTime, Touch per app, Date & Time Year..Minute, Reboot / Shutdown), Toggle (status with `SettingApiReadFlagTimeStart`, async or direct poll, `SettingApiActivate`, as the legacy submenu), Action, Custom. ChoiceBinding (`settings_choice_binding.hpp`): `LvSettingValuePage3Base` implements it; the host builds the node's own value page on a hidden "binding host", which then creates no 320x150 view, only its logic (loads, async writes, rollbacks, countdowns); `choice_activate(i)` is the legacy Enter on option i, selection moves and status lines come back through an observer, the page's back callback means done (the host makes a fresh page to show the new value). No value-page logic is copied. A value list of percentages (Brightness levels) becomes a slider row.

Not migrated (D3, P3; the list after P3c; since P3e the Pi boards have none left and the compat path is deleted): Custom nodes (Apps, and the manual time "Save?" step whose factory-time warning is a dialog) opened through the compat path (`settings_native_compat.*`: the legacy page in a compat AppPage, toolbar, LIST touch; its back returned to the native screen) in development builds only, and were hidden in a release build. Now a Custom node (a page of another board) is always hidden. Development (the Keyboard test page only, since P3e) = `APPLAUNCH_DEV=1`, or a build whose channel (`APPLAUNCH_CHANNEL`, default `development` for a local scons build) is `development`; `APPLAUNCH_DEV=0` forces the release behaviour (`settings_native_mode.hpp`). Known gaps: Bluetooth Discoverable with the power off is refused silently (its legacy warning is drawn by the legacy submenu); a value page's own dialogs are not shown (only "Save?" has one, so it stays on the compat path).

Harness: `scenes/settings_native.scene` (root, Screen section, DarkTime list, Brightness slider one step darker / the Pi 3A+ on/off list, five sizes), `scenes/settings_native_touch.scene` (tap, tap-to-open, drag, Esc button at 480x320 and 800x480) are review-only (scene line `review`, no goldens; `scenes/settings_native_compat.scene` was deleted in P3e); every `header` shot is checked by `run.sh header` against the home grid (the status strip from its Bluetooth icon to the right edge pixel-identical, title at the same origin).

## On-screen keyboard widget (P2b, as implemented)
The F1 fallback keyboard (012) as a shell widget for **native pages only**: compat apps and compat pages (at the time: the deck's default Settings, Wi-Fi password, BT PIN, Store search; since P3e the Settings is native) keep today's behaviour (no keyboard; F1 phase 2 is separate).

Rules (F1 + D6): shown only for a focused native text field, when no physical keyboard is present, the setting is Auto and the launcher owns the screen; never summoned, no hide key. It closes when the field stops editing (Esc, Enter, focus leaves, deletion), on page change (`native_ui::begin_page` / `show_home` call `launcher_osk::dismiss()`), under the lock screen, and when a physical keyboard appears (owed key releases sent, latched Shift / Ctrl dropped); a tap on the field (or Enter on it) edits again and brings it back.

Code (`ext_components/cp0_lvgl`):
- `cp0_ui_osk.h/.c` pure C, `tests/test_ui_osk.c`: layout from the tokens, key tables, Shift / Ctrl state machine, key event sequences, presence policy, dialog placement. Key pitch = min((w - 2 SPACE_S - 9 SPACE_S) / 10, 10 mm); key height = 6.5 mm lowered until utility row + 4 rows fit the class cap (Compact 60 %, Standard 62.5 % = the F1 300 px, Wide 50 %, Large 45 % of the height, report 022 section 3.2); **Square** (user test on the HackBerry 720x720, 2026-10-11): the target is 50 % of the height and the keys grow to reach it (past the token if needed; key width unchanged, 10 mm cap), never leaving less above the keyboard than the header + one field with its label (`cp0_ui_osk_field_reserve`: header, SPACE_M, label line, gap, ROW, SPACE_M); utility row 80 % of a letter row; gaps, margins and vertical padding SPACE_S; key area centred.
- `cp0_ui_osk_widget.cpp`: `cp0::ui::OnScreenKeyboard` (on the display's top layer, the approved look: #111 ground, 1 px #333 top line, keys #1c1c1c radius 10, labels #eee, Enter #1f5f8a, pressed lighter, Shift / Ctrl armed light #e8e8e8 with a dark label, locked in the Enter blue; nothing click-focusable, so a key never steals the field's focus) and the `cp0::ui::osk` service (request / release / dismiss, policy asked on request and every 250 ms while a field wants it, bottom inset and listeners, `keep_above_keyboard(obj, top)`: the dialog primitive for P3, centred in the room above the keyboard).
- `cp0_ui_text_field.cpp`: `cp0::ui::TextField` (TextFieldRow): label above a one-line field (ROW token high, roller wide), Text / Number (digits only, number pad) / Password (masked, eye toggle inside the field). Owns the UTF-8 text and cursor; focus starts editing: saves and sets `KBD_INPUT_CONTEXT_TEXT`, the keypad intercept and the text hint, reads `LV_EVENT_KEYBOARD` on its screen, requests the keyboard; every way out restores all three. Keys while editing: printable text inserted, Backspace / Delete, Left / Right / Home / End, Up / Down / Tab move to the previous / next field, Enter submits (default: stop editing), Esc stops editing (Esc again = the page's back).
- `cp0_ui_page.cpp`: `Page::body()` (form column under the header; height = body - inset; the field the keyboard is up for is scrolled into view with `lv_obj_scroll_to_view_recursive`), `clear_body()`; `Roller::set_hidden()`.
- `cp0_keyboard_inject_key.c` (every backend): `cp0_keyboard_inject_key(code, state, mods, utf8)` (F1 phase 1 item 4: press and release both carry the code and the text) and `cp0_keyboard_set_text_hint()` / `get` (item 5). The keyboard injects through the in-process queue, so the Esc moves the Esc state like the toolbar's (hold-to-exit, watchdog) and its release is always sent (finger lost, key or keyboard deleted).
- `cp0_keyboard_presence`: devices now carry their bus (`CP0_KBD_PRESENCE_BUS_BLUETOOTH`), so the policy can treat a Bluetooth keyboard that went away as asleep.

Keys: row 0 Esc, Tab, Ctrl (TARGET wide, at least one key, at most two) and, when they fit (all five sizes), the four arrows one key wide at the right; letters q-p / a-l / Shift z-m Backspace / 123 , space . Enter; 123 page 1-0, `- / : ; ( ) $ & @ "`, `#+= . , ? ! ' Backspace`; #+= page `[ ] { } # % ^ * + =`, `` _ \ | ~ < > ` € £ ¥ ``; number pad 1-9, Backspace 0 Enter (3 keys wide, centred) under the same row 0. Events: a character = its US-layout KEY_* code + UTF-8 (+ SHIFT when the layout needs it, CAPS under Caps lock); with Ctrl on, any key with a code is sent with `KBD_MOD_CTRL` and no text (Ctrl+C = KEY_C + CTRL, press then release); Esc / Backspace / arrows are hold keys (press on finger down, repeat, release on finger up, owed release on press lost / delete), with the control text of a physical key (Esc never takes Ctrl); Tab carries `\t` only in a multi-line field; Enter `\r`. One-shot Shift / Ctrl: tap arms, a second tap within 400 ms locks, a tap on a locked one turns it off, the next character key uses an armed one.

## Native pages (P3a / P3b, as implemented)
Which tree node gets a native page is decided next to the tree: `settings_native_page()` (settings_page.cpp, from the node's own page factory; the Wi-Fi section is the section whose entries hold the Networks page) makes it `SettingsNodeKind::Native`, and `settings_native_panel_create()` (`settings_native_panel.*`) builds it on the host's scaffold. D3 hides only Custom nodes, so **every migrated page shows in a release build** on a native board. On Esc (a key, the header's Esc) the host first asks the page (`SettingsNativePanel::back()`: its dialog, its sub-list), then closes it. The host also makes the page's screen and its container not click-focusable: they are in the page's input group, and a tap beside the roller (wide screens) or on the header used to take the keys' focus away from every widget (found with the TextBlock at 1280x720; the P2a roller had the same gap).

Widgets added (`ext_components/cp0_lvgl`, no geometry in pages):

Key and value side by side when they fit; otherwise the key keeps its width up to 45 % of the row (more when the value is short) and the value takes the rest, cut with dots, or on Compact wrapped onto a second line at the two-line size ((row - 8) / 2 / 1.25 px, even). A key alone longer than the row wraps the same way on every class.
- `cp0::ui::InfoTable`: a Roller of `RowKind::Info` rows (key as the row label, value in the roller's value style, right-aligned). No row action; the highlight still moves (Up / Down, drag, tap) so a long table scrolls; a table stops at its ends; new values with the same keys change in place.

- `cp0_ui_dialog.h/.c` (pure C, `tests/test_ui_dialog.c`) and `cp0::ui::Dialog`: title (HEADING, bold), body (a content column that scrolls), 1-3 buttons in one row (TARGET high; primary = Enter, in the keyboard's Enter blue; cancel = Esc), width DIALOG_MAX_W, padding SPACE_M, gaps SPACE_S, radius RADIUS_M, an optional reserved status line. It sits in the room between the header and the on-screen keyboard and follows the keyboard. When it does not fit: (1) with the keyboard up the buttons go (the keyboard's Enter and Esc act for them); (2) top / bottom padding SPACE_S; (3) the title leaves the box for the page header's title slot, where it replaces the page's title (and the page's status line hides) while it is there (`DialogSpec::page`, `Page::set_title_override`; P3c fix: until then the dialog lay over the header and left a clipped title and covered the Esc button and the status strip); (4) top / bottom padding 2 px; (5) the body scrolls, keeping the field being edited, its label and the status line in view (the label goes first). The header itself (title slot, Esc, status strip) is never covered. A dimmed backdrop over the body takes the page's taps; the header's Esc stays tappable (= Cancel). ## P3e as implemented: the flip (native Settings by default, compat path removed)

Decision (user, final): (c) delete only what is provably unused on every shipped build. The native Settings runs whenever `native_ui::enabled()` (the dpi-scaled backend exists: every Pi board). `settings_ui::native_selected()` reads no environment; `APPLAUNCH_SETTINGS_UI` is gone and there is no compat escape hatch. Without that backend (stock CardputerZero, SDL simulator, emulator) the legacy roller renderer and legacy page classes stay: they are the only Settings there, and the native host still uses `LvSettingValuePage3Base`, `LvglComponensBase`, the page factories as page identities, `settings_menu_roller.hpp`, `settings_submenu_page.*` and helpers of the Wi-Fi, Bluetooth, static-info and RTC page files.

Deleted: `settings_native_compat.{hpp,cpp}` (128 lines; the host's `compat_`, `open_custom()`, the "compat page handles its own Esc" guard and the Custom-row handling went with it: a Custom row is always hidden; no node of the Pi boards is Custom, `tests/test_settings_native_coverage.py`) and `settings_apps_page.{hpp,cpp}` (1,305 lines, the legacy Apps page). `settings_apps_page_factory` stays as a page identity token in `settings_native_apps_page.*` and returns nullptr (the legacy roller tolerates a null page: `settings_menu_roller.hpp`, `settings_submenu_page.cpp`); its jobs and model were already copied into `settings_apps_jobs.*` / `settings_apps_model.*`. Scenes `settings_bt_compat` and `settings_native_compat` were deleted; the no-op `env APPLAUNCH_SETTINGS_UI native` line left every other scene.

Release channel: bundles built by `pizero2w/build.sh` are release builds (`APPLAUNCH_CHANNEL=release` unless the caller sets it), so development-only pages (System > Keyboard test, `settings_ui::dev_pages()`) stay hidden on devices. `tools/dev/wsl-build.sh` still builds `development` (it exports `APPLAUNCH_CHANNEL=development` unless the environment sets it); CI builds `prerelease`. Side effect: About and System "Channel" read `release` on boards now (`development` before for a bundle from `wsl-build.sh`; `main/SConstruct` defaults to `development` for a local scons build; `settings_static_info_page.cpp` and `settings_system_page.cpp` print the raw channel). `docs/dev/checklists/release.md` says so.

New goldens: `scenes/settings.scene` sets no environment, so it renders the native Settings; its 8 goldens (`golden/{640x480,480x320}/settings_{root,screen,root_system,system}.png`) were re-shot on 2026-10-11 as the new deliberate baseline (waits added; `run.sh twice` is stable). The 28 other goldens are byte-identical. `run.sh validate` no longer compares Settings with `docs/screenshots/settings.png` (a 2026-10-03 deck capture of the compat Settings; the root README's screenshots are left as they are).
