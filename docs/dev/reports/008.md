## Findings for the owner (nothing fixed by me)

1. **Sync failure detection does not match the backend.** `--edit-registry` exits 0 for a source that cannot be fetched (it prints `REGISTRY UPDATED <url> ... cached` and records `status=cached` plus the error in `--registries`). `task_sync` tests only `rc == 0`, so: the live row shows `done`, the final status reads `Synced 4 sources` in green, and the curl probe (the only source of `HTTP 404` / `Connection failed` / `No network`) never runs. The failure only appears after the refresh as a red `failed` row, with the reason rebuilt from the error text: only `Bad JSON` or `Download failed` (+ `(cached list)`). Fix idea: treat a `cached`/`error` status in the `REGISTRY UPDATED` line (or re-read `--registries`) as failed and run the probe.
2. **Letter shortcuts never fire from a keyboard** (`U` new in 006, `S`, `A`, `D` older, same on `main`). The keyboard path passes the evdev code to LVGL (KEY_S = 31) while `handle_key` compares ASCII (`key == 's'` = 115). Proof: `S` on the Sources tab started no sync (REG time unchanged), `A` did not open the editor. The Enter path on the rows works, so only the shortcuts and the footer hints "U: update all", "A: add", "S: sync" are dead. Side effect: some letters/digits act as navigation in these pages (KEY_E=18 is LV_KEY_DOWN etc.). Use the `LV_EVENT_KEYBOARD` `utf8` field, as the add editor does.
3. **After a failed dpkg install the backend keeps a pending transaction** (`~/.local/share/cardputerzero-appstore/pending-package.json`). The next other install/update fails in `--prepare-package` with `another package transaction is pending; finish or retry its original operation`, and the page shows it under the headline **`Download failed`** (`m43.png`, wrong). Retrying the same app (Enter, password) recovers and completes it (`45_retry_4.png`). The page should name the pending app and say "retry it", or the headline should not say download.
4. Status line top right is clipped at 172 px: the elapsed seconds and `(2/2)` are not visible for longer app names during Update all (`Downloading Wi-Fi Survey ...`). The empty list text (`No apps: add your source in ...`, `The Store is needed (backen...`) is clipped too. `No apps` also shows during `Loading...` for about 10 s.
5. Update all asks for the password once per app (confirmed, as stated in the hand-off).
