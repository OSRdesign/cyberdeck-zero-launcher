Root cause (from reading `settings_apps_page.cpp` and `apps_backend.cpp`, not confirmed on the deck): `probe_source` calls `apps_backend::run_program("curl", ...)`, and `run_program` starts the child with `execv(binary.c_str(), ...)`. `execv` does not search `PATH`, so a bare `"curl"` ends with `_exit(127)`; `curl_rc = 127` is then neither 0, 6, 7 nor 28, and `sync_failure_reason` returns `Connection failed` for every failure that is not "Bad JSON". Fix idea: call `/usr/bin/curl` (or use `execvp`). Observation: the final status text of a sync shows in green for about 2 seconds before it turns amber/red (`40_2.png`, `40_3.png` green, `40_4.png` red; `m06.png` first frame).
