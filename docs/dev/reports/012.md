### FAIL: "Keyboard needed: wake the Bluetooth keyboard" never appears
Test: replaced the full keyboard by a virtual device that has only Enter, Esc, Tab, Del, Backspace and the arrows (no letters, no space = the state of a sleeping Bluetooth keyboard), restarted the launcher, started MeshCore, opened "+ Add hashtag", Node name and Frequency: all three editors opened normally (`113_nokb_add.png`, `115_nokb_name.png`, `116_nokb_freq.png`) and no message appeared.
Cause (`/proc/bus/input/devices` while an app runs): the launcher creates its own uinput device `applaunch-vkbd` ("Handlers=sysrq kbd event2 rfkill", KEY bits all set, includes letters, Enter and Space) every time it starts an app (APPLAUNCH_STD_KEYBOARD=1; the dmesg shows `input: applaunch-vkbd` at each app start; with no app running the list holds only the touch screen). `input_state.cpp::keyboard_listed()` accepts any such device, so `keyboard_present()` is always true under this launcher, and the check cannot distinguish "no Bluetooth keyboard". Fix suggestion for apps-dev: ignore the device named `applaunch-vkbd` (or require a Bus other than virtual / the node behind `/dev/input/bt-keyboard`), then retest by removing the symlink. Real effect today: with the keyboard asleep the user sees an editor that cannot be typed into (Esc/Cancel by the launcher toolbar still work).
I could not test it literally with no keyboard device at all, because my keys come through a device and my touch injection does not reach the app; the nav-only device above reproduces the same /proc state the app sees.
